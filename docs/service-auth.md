# T21-11 — Per-service JWT overrides

7 November 2026. The existing `GLOBAL_SKIP_AUTH_FLAG=True` source default is
preserved. Each of the five service overrides takes precedence over it.

| Environment variable | NATS base subject |
| --- | --- |
| `AUTH_INFERENCE` | `inference.tox21.smiles` |
| `AUTH_RDKIT_PROPERTIES` | `rdkit_api.get_molecule_properties` |
| `AUTH_RDKIT_CANONICAL_SMILES` | `rdkit_api.to_canonical_smiles` |
| `AUTH_RDKIT_SAME_STRUCTURE` | `rdkit_api.are_same_structure` |
| `AUTH_PUBCHEM_IUPAC_NAME` | `pcp_api.get_iupac_name_from_smiles` |

Only these exact lowercase values are accepted:

| Value | Effective behavior, regardless of global |
| --- | --- |
| `allow` | Skip JWT verification |
| `require-jwt` | Require a valid RS256 JWT, audience `mercurion-api` |
| `disabled` (also omitted variable) | Inherit the global behavior |

The owner approved `require-jwt` instead of the earlier planning spelling
`deny-withouth-access-token`; that spelling is not an accepted alias.
`disabled` does not switch off a service. All payload/domain validation remains.
Example: `AUTH_INFERENCE=require-jwt` protects inference even with the public
global default. `AUTH_RDKIT_PROPERTIES=allow` keeps properties public even if
the source global has been set to require JWT.

Pydantic validates all five settings before model/key/broker initialization.
Empty/whitespace, uppercase, unknown values and explicit `None` fail validation;
they do not fall back to `disabled`. A bare dotenv declaration is also invalid.
Only absence invokes the default. Development/test dotenv input and process
precedence follow the existing loader; staging/production use process env only.
Diagnostics name the invalid fields without echoing supplied values.

Effective policies are snapshotted at bootstrap. Restart to change them; there
is no live configuration reload. The same resolved policy drives the request
schema's token requirement and JWT validation. If any service needs JWT, load
one RSA public PEM from `JWT_PUBLIC_KEY_PATH` before model/NATS initialization.
If all five are public (including five `allow` overrides over restrictive global),
no PEM is read. A required missing/invalid PEM aborts startup, with no auth bypass.

Subject names, envelopes and response/error shapes are unchanged. Missing token
is an invalid request; a structurally valid but unverifiable/expired token gives
`Invalid or expired access token`. `allow` retains the existing behavior of
ignoring even malformed optional tokens, but still validates the other fields.

## Deployment and compatibility

The supplied Compose fragments forward these five optional variables. They use
`${AUTH_INFERENCE-disabled}` (single minus), not `${AUTH_INFERENCE:-disabled}`:
an explicitly empty setting must reach Pydantic and fail. Mount the public PEM
read-only and set `JWT_PUBLIC_KEY_PATH` when enabling any protected service.
No real key file or mount path is selected automatically.

Web consumers currently calling an endpoint without a token will be rejected
if an operator protects it. This task does not automatically forward user
credentials, enable authentication on deployed services or alter Web sessions.
There is no new global env switch, key rotation, role/ACL system or endpoint.
